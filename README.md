# ใจส่งถึงบ้าน

ระบบจองรถรับ-ส่งผู้สูงอายุและผู้ป่วยไปโรงพยาบาล ที่เทศบาลใช้จัดคิวให้อาสาสมัครขับรถ ผู้โดยสารจองได้เอง หรือให้ผู้ดูแลจองให้ เจ้าหน้าที่ดูคิว มอบหมายคนขับ แล้วติดตามรถบนแผนที่ได้ระหว่างเดินทาง

ผู้ใช้ล็อกอินด้วยบัญชี LINE ไม่ต้องสมัครสมาชิกเพิ่ม ชื่อเทศบาลที่เห็นในหน้าเว็บ (เทศบาลนครสุขภิรมย์) เป็นชื่อตัวอย่าง เปลี่ยนเป็นของหน่วยงานตัวเองได้

## ใครใช้ทำอะไร

- **ผู้สูงอายุ / ประชาชน (USERS)** จองคิวรับ-ส่ง ดูสถานะ ยืนยันเมื่อเสร็จงาน
- **ผู้ดูแล (CAREGIVER)** จองแทนคนในความดูแล และจัดการรายชื่อคนที่ดูแลอยู่
- **คนขับอาสา (DRIVE)** รับงาน เลือกรถ ดูเส้นทาง อัปเดตสถานะ
- **ผู้ดูแลระหว่างเดินทาง (CAREU)** ไปกับรถเพื่อดูแลผู้ป่วย
- **เจ้าหน้าที่ (STAFF)** อนุมัติคำขอ จัดคิว มอบหมายงาน ดูรายงาน จัดการรถ
- **ผู้ดูแลระบบ (ADMIN)** ตั้งสิทธิ์ ดูบันทึกการใช้งาน ปรับค่าระบบ

คนที่ล็อกอินด้วย LINE ครั้งแรกจะยังไม่มีบทบาท ระบบพาไปหน้าเลือกบทบาทก่อน ส่วนบทบาทอื่นๆ ต้องขอสิทธิ์แล้วให้เจ้าหน้าที่หรือผู้ดูแลระบบอนุมัติ

## วิธีใช้งาน

เปิดหน้าเว็บแล้วกดปุ่ม "เข้าสู่ระบบด้วย LINE" ครั้งแรกระบบจะพาไปเลือกบทบาทและกรอกข้อมูลพื้นฐาน (ชื่อ เบอร์โทร ที่อยู่) หลังจากนั้นล็อกอินครั้งต่อไปจะเข้าหน้าหลักของบทบาทนั้นเลย

ผู้สูงอายุหรือผู้ดูแล จองคิวจากหน้าหลัก เลือกโรงพยาบาล วันและช่วงเวลา จุดรับ แล้วรอเจ้าหน้าที่หรืออาสาสมัครรับงาน เมื่อมีคนรับจะได้แจ้งเตือนทาง LINE และดูรถบนแผนที่ได้ตอนใกล้ถึง จบงานแล้วมีหน้าให้คะแนนบริการ

คนขับอาสา เปิดรายการงานที่รอรับ กดรับงาน เลือกรถที่ใช้ แล้วกดอัปเดตสถานะตามขั้นตอน (ออกเดินทาง รับผู้โดยสาร ถึงโรงพยาบาล จบงาน) ตำแหน่งรถส่งขึ้นแผนที่อัตโนมัติ เมื่อจบงานได้คะแนนสะสมไปแลกของรางวัล

เจ้าหน้าที่ ดูคิวทั้งหมด อนุมัติคำขอ (เช่น ขอเป็นคนขับ ขอแก้ข้อมูลส่วนตัว) มอบหมายคนขับให้งานที่ยังไม่มีคนรับ จัดการข้อมูลรถ โรงพยาบาล ของรางวัล และดูรายงานสรุป

ผู้ดูแลระบบ ทำได้ทุกอย่างที่เจ้าหน้าที่ทำ และตั้งสิทธิ์ ดูบันทึกการใช้งาน ปรับค่าระบบ

## ที่มีอยู่ตอนนี้

- จองคิวรับ-ส่ง เลือกช่วงเวลา และให้คนอื่นจองแทนได้
- จัดคิวและมอบหมายคนขับกับผู้ดูแลระหว่างเดินทาง
- แผนที่ติดตามรถแบบสด (Socket.IO กับ Mapbox)
- ข้อมูลรถ โรงพยาบาล โรค และอุปกรณ์ช่วยเดินทาง
- คะแนนสะสมของอาสาสมัครและของรางวัลที่แลกได้
- ให้คะแนนบริการหลังจบงาน
- แจ้งเตือนผ่าน LINE และในเว็บ
- อัปโหลดรูป (ย่อขนาดอัตโนมัติ) บันทึกการใช้งาน และงานตั้งเวลาเบื้องหลัง
- ปฏิทินและรายงานสรุปสำหรับเจ้าหน้าที่

## เครื่องมือที่ใช้

หน้าเว็บเป็น Next.js 16 กับ React 19 และ TypeScript จัดหน้าด้วย Tailwind และ MUI แผนที่ใช้ Mapbox ส่วนหลังบ้านเป็น NestJS 11 ต่อ PostgreSQL ผ่าน Prisma 7 ยืนยันตัวตนด้วย JWT ที่เก็บในคุกกี้แบบ HttpOnly และมี Swagger ให้ดูรายการ API

## โครงสร้าง

```text
backend/    NestJS: auth, user, งานและคิว, รถ, แจ้งเตือน, LINE, อัปโหลด ฯลฯ
frontend/   Next.js: หน้าของแต่ละบทบาท (elderly, caregiver, volunteer, staff, admin)
docker-compose.yml       postgres + backend + frontend
docker-compose.dev.yml   แบบสำหรับพัฒนา
DOCKER.md                ขั้นตอนใช้ Docker
```

โค้ดฝั่งหลังบ้านอยู่ใน `backend/src/modules` แยกเป็น core (auth, user), business (job, queue, vehicle, hospital ...), features (points, reward, upload ...), integration (LINE, geocode, location) และ system (notification, scheduler, activity-log)

## การติดตั้ง

สิ่งที่ต้องมี: Node.js 20 ขึ้นไป, PostgreSQL 16 (ใช้ Docker เปิดเฉพาะฐานข้อมูลก็ได้), บัญชี LINE Developers สำหรับสร้างช่อง LINE Login และถ้าจะใช้แผนที่ต้องมี token ของ Mapbox

### รันบนเครื่องตัวเอง

```bash
docker compose up -d postgres
```

หลังบ้าน

```bash
cd backend
npm install
# สร้างไฟล์ .env ตามหัวข้อด้านล่าง
npm run start:dev
```

หน้าเว็บ

```bash
cd frontend
npm install
# สร้างไฟล์ .env ตามหัวข้อด้านล่าง
npm run dev
```

หน้าเว็บอยู่ที่ http://localhost:3000 หลังบ้านอยู่ที่พอร์ต 3001

### ตัวแปรสภาพแวดล้อม

ไม่มีไฟล์ตัวอย่างใน repo และผมไม่ได้เอาไฟล์ `.env` จริงขึ้นมาด้วย ชื่อตัวแปรที่โค้ดอ่านมีดังนี้

หลังบ้าน (`backend/.env`)

```text
DATABASE_URL            เช่น postgresql://user:pass@localhost:5432/volunteer_smart?schema=public
JWT_SECRET, JWT_EXPIRES_IN, COOKIE_SECRET
PORT                    พอร์ตของหลังบ้าน
FRONTEND_URL            ที่อยู่หน้าเว็บ ต้องตรงกับที่เปิดจริงทุกตัวอักษร (ใช้ตั้ง CORS)
LINE_CHANNEL_ID, LINE_CHANNEL_SECRET        ช่อง LINE Login
LINE_MESSAGING_CHANNEL_ID, LINE_MESSAGING_CHANNEL_SECRET, LINE_MESSAGING_ACCESS_TOKEN   ช่อง Messaging API (ส่งแจ้งเตือน)
LINE_CALLBACK_URL
MAPBOX_TOKEN
SWAGGER_USER, SWAGGER_PASSWORD     รหัสเข้าหน้า Swagger
E_SERVICE_API_KEY, E_SERVICE_CODE, E_SERVICE_MUNICIPALITY_ID   ใช้กับการยืนยันที่พักอาศัย ถ้าไม่ใช้ส่วนนั้นปล่อยว่างได้
```

หน้าเว็บ (`frontend/.env`)

```text
NEXT_PUBLIC_API_URL        ที่อยู่หลังบ้าน
NEXT_PUBLIC_MAPBOX_TOKEN, NEXT_PUBLIC_MAPBOX_STYLE
NEXT_PUBLIC_LIFF_ID
```

ตัวแปรที่ขึ้นต้นด้วย `NEXT_PUBLIC_` ถูกฝังตอน build ถ้าเปลี่ยนค่าต้อง build ใหม่ ไม่ใช่แค่รีสตาร์ท

### ตั้งค่า LINE Login

สร้างช่อง LINE Login ใน LINE Developers แล้วใส่ Callback URL เป็น `<FRONTEND_URL>/auth/line-callback` หลังบ้านจะตรวจว่า redirect กลับมาที่โดเมนของ `FRONTEND_URL` เท่านั้น เว็บกับหลังบ้านต้องเปิดจากโดเมนเดียวกัน (พอร์ตต่างกันได้) เพราะคุกกี้ล็อกอินตั้งเป็น SameSite=Strict และ CORS เปิดแบบส่งคุกกี้

### รันจริง (production)

ทำตามนี้ตามลำดับ

1. สร้างฐานข้อมูล แล้วใส่ `DATABASE_URL` ใน `backend/.env` (ดูหัวข้อฐานข้อมูลด้านล่างเรื่องการสร้างตาราง)
2. หลังบ้าน: `npm install`, `npm run build`, `npm run start:prod` (หรือใช้ pm2 ครอบก็ได้)
3. หน้าเว็บ: ใส่ `NEXT_PUBLIC_API_URL` และตัวแปร `NEXT_PUBLIC_` อื่นๆ ใน `frontend/.env` แล้ว `npm install`, `npm run build`, `npm run start`
4. ใส่ Callback URL ของ LINE Login ให้ตรงกับโดเมนที่เปิดจริง
5. ล็อกอินด้วย LINE หนึ่งครั้ง แล้วตั้งตัวเองเป็นผู้ดูแลระบบตามหัวข้อฐานข้อมูล

ถ้าใช้ Docker มี `docker-compose.yml` ที่เปิด postgres, backend และ frontend ให้พร้อมกัน ดู `DOCKER.md` ประกอบ

## ฐานข้อมูล

Schema อยู่ที่ `backend/prisma/schema.prisma` มีคำสั่ง `npm run prisma:migrate:deploy` และ `prisma:studio` ให้ใช้

มีเรื่องที่ควรรู้ไว้ก่อน ไฟล์ migration ในโฟลเดอร์ `backend/prisma/migrations` ตามไม่ทัน schema ตอนที่ผมนำขึ้นเครื่องจริงพบว่าขาดบางคอลัมน์ (เช่น `users.allowed_roles`) และบางตาราง ผมแก้ด้วยการเขียน SQL เพิ่มบนฐานข้อมูลของผมเอง ยังไม่ได้ย้อนมาทำเป็น migration ใน repo ถ้าสร้างฐานข้อมูลเปล่าแล้วรัน `migrate deploy` อาจเจอ error แปลกๆ ตอนใช้งาน ทางที่น่าจะง่ายสำหรับเครื่องพัฒนาคือ `npx prisma db push` แต่ผมยังไม่ได้ลองกับฐานข้อมูลเปล่าจริง ถ้าลองแล้วเป็นอย่างไรอยากให้ช่วยแก้ตรงนี้ใน README ด้วย

ตั้งผู้ดูแลระบบคนแรกด้วยการแก้คอลัมน์ `role` ของผู้ใช้ในฐานข้อมูลเป็น `ADMIN` หลังจากล็อกอินด้วย LINE ครั้งหนึ่งแล้ว

## ข้อควรระวัง

- repo นี้ไม่มีข้อมูลตัวอย่าง ต้องสร้างผู้ใช้เองผ่านการล็อกอินด้วย LINE แล้วตั้งบทบาทให้
- `DOCKER.md` อาจมีตัวแปรบางตัวที่ไม่ตรงกับตอนนี้ ให้เทียบกับรายการตัวแปรด้านบน
- ส่วนยืนยันที่พักอาศัยเชื่อมกับบริการภายนอกและยังไม่ได้ทดสอบกับของจริง ถ้าไม่ได้ใช้ ปล่อยตัวแปร `E_SERVICE_*` ว่างไว้
